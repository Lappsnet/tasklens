# TaskLens Android app (Trusted Web Activity)

P0-5. The Play build is a thin Trusted Web Activity wrapper around the
production PWA — **it contains no Wearables SDK**. Glasses features stay in
`apps/glasses-android` for testers via the Meta Wearables Developer Center
release channel.

## One-time setup (needs JDK 17 + Android SDK + the production URL live)

```sh
npm i -g @bubblewrap/cli
cd apps/android-twa
# Generate an upload keystore (keep android.keystore + passwords out of git):
keytool -genkeypair -v -keystore android.keystore -alias android \
  -keyalg RSA -keysize 2048 -validity 10000
# Verify the committed manifest against the live PWA, then build:
bubblewrap build --manifest ./twa-manifest.json
```

Before building, confirm in `twa-manifest.json`:
- `host` matches the deployed production domain (`NEXT_PUBLIC_APP_URL`).
- `targetSdkVersion` matches what Play Console currently requires
  (36 at the time of writing — re-check at submission; docs beat this file).

## Connecting the site (order matters)

1. Upload the `.aab` to Play Console (internal testing). Enroll in **Play app
   signing** and copy the **app-signing SHA-256** fingerprint.
2. Set `ASSETLINKS_SHA256_FINGERPRINTS=<that fingerprint>` on the Vercel
   project and redeploy — `/.well-known/assetlinks.json` then serves it.
3. Re-install: the app must open with **no browser bar** (that proves the
   asset-links handshake). If the bar shows, the fingerprint/host is wrong.
4. Promote internal → **closed testing by Oct 31**.

## Store checklist (see `docs/store/`)

- `icon-512.png`, `feature-1024x500.png` (generated by
  `apps/web/scripts/gen-pwa-assets.py`), 8 phone screenshots 1080x1920
  captured from the real app, short + full descriptions (ES/EN).
- Data-safety answers mirror `/privacy`: camera, microphone, approximate
  location, photos (app functionality, never sold); payments handled by PayPal.
